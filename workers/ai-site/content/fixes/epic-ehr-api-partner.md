## Epic EHR API vs custom integration: what is the difference?

The Epic EHR API is Epic's developer interface for building apps and workflows that connect to Epic systems through standards such as FHIR and SMART on FHIR. A custom integration service is the hands-on implementation work that plans the data flow, builds the app, tests it in the sandbox and prepares it for each health system's approval.

If you are a SaaS team, the API is the tool. The custom integration is the project.

## What is building directly on Epic best for?

Building directly is best for teams that want access to a widely used EHR platform and can handle product, engineering and compliance work themselves.

Epic publishes developer resources on open.epic, including the Epic FHIR API and sandbox test patients. That makes it possible to prove an idea before any hospital is involved, which is valuable if you already have engineers who know FHIR, OAuth, app registration and healthcare deployment.

### Pros

- **Free to start.** Epic's standards-based FHIR APIs are free for developers to build and test against.
- **Standards-based.** Epic supports FHIR and SMART on FHIR, which helps with modern app patterns.
- **Sandbox first.** You can test with sample data before involving a live health system.
- **Direct platform access.** Good if you want to build tightly around Epic workflows.

### Cons

- **You still need approval.** Going live depends on each hospital or clinic's review and enablement.
- **It is not an implementation service.** Epic gives you the API and documentation, not the delivery team.
- **Health systems differ.** One organization's security review, scopes or workflow can differ from another's.
- **Integration is only one part of the project.** Your team still has to handle mapping, testing, launch, monitoring and support.

## How do Epic integrations work in practice?

Epic integrations usually start in the developer sandbox, then move into health-system review and enablement:

- **Register the app** on Epic's developer site.
- **Choose the launch model**, for example SMART on FHIR for patient or clinician access.
- **Build against the sandbox** with test patients and confirm the data flow.
- **Map the workflow:** decide what data is read, written and shown.
- **Prepare for security review.** Each hospital or clinic may have its own process.
- **Launch with the health system,** then monitor, fix and improve.

That is why integration projects often fail late: the API is available early, but go-live depends on people, process and review.

- **Do you need a fixed scope and accountable timeline?** If yes, ask for proposals.

### What is the difference between EMR and EHR?

An EMR is a digital chart for one practice. An EHR is designed to share data across providers, labs, pharmacies and the patient. Epic is generally treated as an EHR platform, and many integrations use FHIR.

Yes, Epic supports SMART on FHIR for patient and clinician-facing app launches.
