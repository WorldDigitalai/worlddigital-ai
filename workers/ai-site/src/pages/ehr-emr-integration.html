How to integrate with Epic

How to integrate with Epic, step by step.

Epic publishes its developer resources on open.epic, including the Epic FHIR API and a sandbox with test patients. Building and testing there costs developers nothing, so you can prove an idea before any hospital is involved.

Going live is different. Each hospital or clinic decides which apps run on its Epic system, so the integration needs their security review and approval. Planning for that step early is what keeps an Epic integration on schedule.

Optional Epic programs

Epic's Vendor Services program adds support and testing tools for a fee, and the Epic Showroom, which replaced App Orchard, is where connected apps can be listed. Neither is required to start.

  1. Register the app. Set it up on Epic's developer site to get client IDs and sandbox access.
  2. Pick the sign-in. SMART on FHIR for patient or clinician launch, or Backend Services for system-to-system data.
  3. Build in the sandbox. Test against the Epic FHIR API with fictional patients, asking only for the data you need.
  4. Pass the review. Each health system checks security and privacy, then enables the app in its own Epic environment.
  5. Launch and measure. Go live with their IT team and track time saved, no-shows and patient questions answered.
EHR vs. EMR

EHR vs. EMR: what’s the difference?

An EMR (electronic medical record) is the digital chart a single practice keeps for its own patients. An EHR (electronic health record) is designed to travel: it shares information with other providers, labs, pharmacies and the patient.

Most systems clinics use today, including Epic, work as EHRs. That matters for EHR interoperability, because modern EHRs expose standard APIs, so a website, app or AI tool can connect without custom one-off interfaces.

The standards behind it

HL7 FHIR

Defines how health data like patients, appointments and medications is structured and exchanged. Most new EHR integration software is built on FHIR R4.

SMART on FHIR

Handles secure sign-in, so patients and clinicians approve an app without sharing passwords, across Epic and other certified EHRs.

HL7 v2

The older message format many hospitals still use for feeds like admissions and lab results. HL7 integration is often part of the same project.

FAQ

Common questions.

What is the difference between EMR and EHR?

An EMR (electronic medical record) is the digital chart one practice keeps for its own patients. An EHR (electronic health record) is built to share that record with other providers, labs, pharmacies and the patient. Most modern systems, including Epic, work as EHRs, and integration usually happens through the FHIR standard.

How do you integrate with Epic?

Register the app on Epic's developer site, build and test it against the Epic FHIR API in Epic's sandbox with test patients, then have each hospital or clinic review and enable it in their own Epic system. We handle that whole path, including preparing for each health system's security review.

Is the Epic API free to use?

Epic's standards-based FHIR APIs are free for developers to build and test against. Health systems can have their own costs to turn on API access, and Epic's Vendor Services program is an optional paid add-on for developers who want extra support and testing tools.

Can you track which ads book patient visits without sharing patient data?

Yes. Each booking keeps the ad click ID and campaign tags inside a HIPAA, BAA-covered environment. Only de-identified counts per campaign go back to Google Ads, and names, contact details and visit reasons never reach ad platforms.

What is SMART on FHIR?

SMART on FHIR is the open standard for how apps sign in to an EHR and request access to data. Patients and clinicians approve an app without sharing passwords, and the same approach works across Epic and other certified EHRs.

Which other EHR and EMR systems can you work with?

Any system that offers standards-based APIs, which today includes most major certified EHRs. FHIR integration covers modern apps, HL7 v2 integration covers older feeds, and each vendor gets its own testing.

How do you handle HIPAA and patient data?

Projects that touch patient data start with a Business Associate Agreement. We request only the data the use case needs, keep it encrypted in transit and at rest, log access, and avoid storing patient data when the app can read it live from the EHR instead.

How long does an EHR integration take?

A working prototype against a vendor sandbox comes first and is the fastest part. Most of the timeline after that is set by the health system's security review, app approval and go-live scheduling, so we plan around it from the first call.
